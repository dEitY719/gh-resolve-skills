막힌 PR 을
다시 머지 가능하게

GitHub 이 머지 버튼을 회색으로 만드는 이유는 셋이고, 이 플러그인에는 이유마다 스킬이 하나씩 있다. GitHub 이 무엇을 문제 삼고 있는지로 고르는 것이지, 내가 무엇을 고치고 싶은지로 고르는 것이 아니다.

세 가지 blocker

Required checks are red

/gh-resolve:ci-fail

실패한 check 의 로그를 읽어 원인을 특정하고, 로컬에서 고친 뒤 CI 가 돌린 바로 그 명령으로 재검증한다. fast-forward push 만 하고, push 가 성공한 뒤에야 CI fail 라벨을 뗀다. job 을 무작정 다시 돌리는 일은 없다.

설명서 실행 기록
Branch has conflicts

/gh-resolve:conflict

head 를 base 위로 rebase 하면서 충돌 파일마다 사용자의 의도를 묻고 해소한다. 애매한 hunk 를 추측하지 않고, merge commit 을 만들지 않으며, --force-with-lease 가 거부되면 대신 재시도하지 않고 멈춘다.

설명서 실행 기록
Head is behind its base

/gh-resolve:outdated

가장 싼 경우 — base 는 움직였지만 충돌은 없다. 클린 rebase 후 --force-with-lease push. 멱등해서 다시 돌려도 안전하고, rebase 가 충돌을 내는 순간 스스로 풀지 않고 exit code 로 conflict 에 넘긴다.

설명서 실행 기록

왜 하나로 합치지 않았나

셋은 실패 양상이 다르고, push 정책이 다르고, 멈추는 규칙이 다르다. 합치면 이 셋을 안전하게 유지하는 단 하나의 조건 — 지금 보고 있는 blocker 가 무엇인지 아는 것 — 이 흐려진다.

push 정책이 다르다

ci-fail 은 fast-forward 만 한다. 나머지 둘은 published history 를 다시 쓰므로 --force-with-lease 를 쓰고, plain --force 는 어느 쪽도 쓰지 않는다.

멈추는 규칙이 다르다

outdated 는 충돌을 만나면 abort 하고 넘긴다. conflict 는 애매하면 묻고 기다린다. ci-fail 은 로컬 검증이 빨가면 push 하지 않는다.

공통 안전 계약

셋 다 default branch 에서는 실행을 거부하고, 히스토리를 건드리기 전에 BACKUP_SHA 를 출력하며, 모든 gh 호출을 GH_HOST= 로 호스트 고정한다.

이 페이지들의 출처

각 페이지는 docs/skill-guides/ 와 docs/skill-output/ 의 Markdown 원본에서 생성된다. 실행 기록은 실제 PR 을 대상으로 돌린 결과이며, 미실행 단계는 그 사유와 함께 표시된다.
